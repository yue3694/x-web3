# Web3 University — 需求规格

## 概述

Web3 University 是一个面向学生、老师和平台运营方的在线课程平台：高频业务数据保存在 PostgreSQL，课程购买与证书归属由 EVM 链提供可验证凭证。系统采用单一 Web 前端、Go API/Worker、Foundry 合约和 AWS 基础设施，并在现有 pnpm monorepo 中演进。

## 目标与边界

### 产品目标

- 学生可登录、浏览课程、使用 YD Token 购买、学习并获得 ERC-721 课程证书。
- 老师可创建、编辑、提交课程，管理章节/视频并查看自己的课程数据。
- 隐藏入口的超管可审核课程、管理用户/角色、查看全局业务与链上同步状态。
- 链上只承载结算、所有权和可验证事件；课程、视频、评论、学习进度等业务数据不上链。
- 规格可供 AI Agent 按依赖顺序开发、测试和同步文档。

### MVP（首个可上线版本）

- Privy 登录、用户自动开户、单用户多钱包绑定。
- Student / Teacher / Super Admin 三类角色与后端强制 RBAC。
- 课程管理、审核、发布、检索和详情展示。
- 视频学习进度、课程完成判定。
- YD Token 支付、CourseMarket 订单结算、链上事件同步与失败补偿。
- 完课证书 ERC-721 铸造与个人中心展示。
- Sepolia 测试网部署、AWS 非生产环境、审计日志和基础监控。

### 后续阶段（不阻塞 MVP）

- Uniswap YD/USDC 主池及可选 YD/WETH 池的兑换入口与流动性运营。
- Chainlink Automation/Functions 驱动的自动化或外部证明；不得成为课程完成的唯一可信来源。
- 评论审核、讲师结算、退款、优惠、DAO 治理、移动端 App、多链和法币入金。

## 角色与用户故事

- 作为访客，我想浏览已发布课程，以便决定是否注册和购买。
- 作为学生，我想用 Privy 登录并绑定钱包，以便在同一账号下使用 Web2 与 Web3 功能。
- 作为学生，我想使用 YD Token 购买课程，以便获得课程访问权。
- 作为学生，我想持续保存学习进度并在完成课程后领取证书，以便证明学习成果。
- 作为老师，我想编辑课程、章节和视频并提交审核，以便发布教学内容。
- 作为老师，我想查看自己课程的销量和学习数据，以便优化内容。
- 作为超管，我想审核课程、管理权限和检查异常链上交易，以便保障平台运营。
- 作为运维人员，我想重放漏记的链上事件并观察同步水位，以便恢复最终一致性。

## 功能需求

### 身份与权限

1. **F-001** 系统以数据库 `users.id`（UUID）作为唯一用户标识，不以钱包地址作为用户主键。
2. **F-002** 后端必须验证 Privy access token，按 `privy_user_id` 幂等创建或读取用户。
3. **F-003** 一个用户可绑定多个钱包；同一 `chain_id + normalized_address` 只能属于一个用户。
4. **F-004** 系统支持 `student`、`teacher`、`super_admin` 角色以及 permission 级授权；新用户默认仅为 student。
5. **F-005** teacher 角色需申请/审批或由超管授予；客户端声明不能提升权限。
6. **F-006** 超管页面不出现在公开导航中，但安全性必须由 API 鉴权保证，而不是依赖隐藏 URL。
7. **F-007** 用户可查看会话、钱包和角色信息；解绑最后一个钱包不得破坏其 Privy 账号与历史订单。

### 课程与内容

8. **F-008** 老师可创建、编辑、归档课程以及维护章节、课时、视频元数据和排序。
9. **F-009** 课程状态至少包含 `draft → pending_review → published → archived`，驳回后回到 `draft` 并记录原因。
10. **F-010** 只有课程作者可修改其草稿；超管可审核、下架和查看全部课程。
11. **F-011** 访客只能读取已发布课程；已购买学生可以读取受保护的播放凭证和课程内容。
12. **F-012** 视频对象存入 S3，数据库只保存元数据与对象键；访问通过短时签名 URL 或 CloudFront 签名凭证控制。
13. **F-013** 支持课程列表分页、分类、关键词、老师和价格筛选，排序结果稳定。
14. **F-014** 学生可对已购买课程发表评论；评论保留审核状态和软删除记录。

### 订单与链上购买

15. **F-015** 课程链下 ID 与链上 `courseKey` 一一映射，映射不可因标题或内容修改而改变。
16. **F-016** 已发布付费课程包含支付 token、原子单位价格、目标链、CourseMarket 地址和价格版本。
17. **F-017** 学生购买前，后端创建带过期时间的购买意图，冻结课程、价格版本、买家钱包和链 ID。
18. **F-018** 前端执行 ERC-20 allowance 检查，必要时 `approve`，再调用 `CourseMarket.buyCourse`；UI 必须展示待签名、待确认、成功和失败状态。
19. **F-019** CourseMarket 必须阻止零地址、零价配置、重复购买、错误 token/金额和未授权课程配置。
20. **F-020** Worker 按 `(chain_id, tx_hash, log_index)` 幂等消费事件，并在达到配置的确认数后将订单置为 `confirmed`、授予 enrollment。
21. **F-021** API 不得仅凭前端提交的交易哈希授予课程访问；必须校验 receipt、合约地址、事件签名、买家、课程、token、金额和链 ID。
22. **F-022** 链重组、RPC 暂时失败和重复事件须可恢复；系统支持按区块范围回放和人工对账。
23. **F-023** 订单状态至少包含 `created / submitted / confirming / confirmed / failed / expired / reorged`，所有变更可审计。

### 学习与证书

24. **F-024** 只有有效 enrollment 可访问受保护课程并写入学习进度。
25. **F-025** 学习进度以 user、course、lesson 唯一，更新需幂等且不得倒退；服务端记录完成时间。
26. **F-026** 课程完成规则由服务端按必修课时计算，阈值可配置且有版本记录。
27. **F-027** 完课后创建唯一证书铸造任务；同一用户、课程和证书版本只能成功铸造一次。
28. **F-028** CertificateNFT 仅允许 `MINTER_ROLE` 铸造，token 关联稳定的证书 ID 和不可变/内容寻址 metadata URI。
29. **F-029** Worker 校验完课资格后发起 mint、等待确认并保存 chain、tx hash、token ID 和状态。
30. **F-030** 用户可在个人中心查看课程访问权、订单、学习进度和链上证书。

### Token、DEX 与 Oracle

31. **F-031** YD Token 基于 OpenZeppelin ERC-20；初始供应、最大供应、铸造/暂停权限和 treasury 必须在部署配置中显式定义。
32. **F-032** 高权限合约角色由多签持有；生产环境不允许长期由单个热钱包控制。
33. **F-033** Uniswap 集成优先 YD/USDC 单一主池，前端报价必须设置滑点、deadline、最小输出并提示价格影响。
34. **F-034** Chainlink 只用于已定义的外部价格、自动化或证明场景；Oracle 结果需检查 feed、精度、更新时间和异常边界。

### 管理、审计与运维

35. **F-035** 超管可管理角色、课程审核、订单/同步异常和证书重试；高风险操作需二次确认并记录审计日志。
36. **F-036** 系统提供健康检查、结构化日志、指标和告警，覆盖 API、数据库、队列、RPC 水位和失败交易。
37. **F-037** 所有跨系统写操作使用 idempotency key 或唯一约束，支持安全重试。
38. **F-038** AI Agent 开发必须先读规格，按 migration → API/合约 → 测试 → UI → 文档顺序提交，禁止绕过 RBAC 或把业务数据迁上链。

## 核心业务规则

- **数据权威**：用户、课程、订单视图、学习进度以 PostgreSQL 为查询权威；支付和 NFT 所有权以目标链为最终权威。
- **一致性**：链上到链下采用至少一次消费 + 数据库唯一约束，实现最终一致性；不宣称分布式强一致。
- **金额**：金额一律使用 token 最小单位的整数/decimal，不使用浮点数；同时保存 token decimals 和价格版本。
- **身份**：用户、Privy 身份和钱包分离建模；钱包签名只能证明地址控制权，不能替代平台角色授权。
- **课程访问**：仅 `confirmed` 订单产生 enrollment；前端本地状态和 pending 交易均不能解锁内容。
- **证书**：完课记录先落库，再异步铸造；链上失败可重试但不得重复铸造。

## 非功能需求

- **性能**：普通 API P95 ≤ 300 ms（不含第三方/RPC）；课程列表首屏 P95 ≤ 1 s；默认分页 ≤ 50 条。
- **可用性**：MVP 月可用性目标 99.5%；RPC 故障不能影响已缓存的公开课程浏览。
- **安全**：OWASP 基线、Privy token 校验、后端 RBAC、限流、CORS 白名单、参数校验、密钥进入 AWS Secrets Manager/KMS；合约遵循 CEI、ReentrancyGuard、Pausable、AccessControl 和 pull-payment 原则。
- **隐私**：仅收集必要个人信息；日志不得记录 token、私钥、完整签名或敏感资料；定义数据删除与保留策略。
- **兼容性**：桌面和移动端现代浏览器；目标链至少 Sepolia，生产链在上线评审时确定；错误网络必须阻止交易并引导切换。
- **可访问性**：关键购买、学习和管理流程达到 WCAG 2.1 AA 的键盘、焦点和对比度要求。
- **可测试性**：Go 单元/集成测试、Foundry 单测/fuzz/invariant、前端组件测试和关键路径 E2E；生产合约行覆盖率 ≥ 90%。
- **可观测性**：所有请求、订单、链事件和 mint 任务具有 correlation ID；同步延迟、失败率、余额和管理员操作可告警。

## 验收标准

- [ ] **AC-001** 新 Privy 用户首次登录仅创建一个 users 记录，重复登录不重复创建。
- [ ] **AC-002** 同一用户可绑定两个钱包；已属于他人的钱包绑定会被拒绝并审计。
- [ ] **AC-003** Student 调用老师/超管 API 返回 403；篡改前端角色不会改变结果。
- [ ] **AC-004** 老师可完成草稿、提交审核；只有超管可发布或驳回，状态跳转非法时返回 409。
- [ ] **AC-005** 未购买用户无法取得受保护视频凭证，已确认 enrollment 用户可以。
- [ ] **AC-006** 课程购买冻结价格版本，之后改价不影响已创建且未过期的购买意图。
- [ ] **AC-007** 正确的 CoursePurchased 事件在确认数达到阈值后只生成一个 confirmed 订单和一个 enrollment。
- [ ] **AC-008** 伪造 tx hash、错误链、错误合约、错误买家或错误金额均不能解锁课程。
- [ ] **AC-009** 重复投递、Worker 重启和区块回放不会产生重复订单、enrollment 或证书。
- [ ] **AC-010** 模拟 reorg 后原事件被标记 reorged，访问权按明确策略冻结并进入人工对账。
- [ ] **AC-011** 学习进度重试不会倒退，达到规则阈值后只产生一个 mint 任务。
- [ ] **AC-012** CertificateNFT 非 MINTER_ROLE 地址铸造失败，同用户同课程不能重复成功铸造。
- [ ] **AC-013** 合约 `forge fmt --check`、单元、fuzz/invariant 测试通过且行覆盖率 ≥ 90%。
- [ ] **AC-014** API、Worker、数据库和 Web 在本地 compose 环境可启动，关键 E2E 流程通过。
- [ ] **AC-015** Sepolia 上完成登录、购买、事件同步、课程访问、完课和证书展示的端到端演示。
- [ ] **AC-016** AWS 非生产环境通过 IaC 部署，密钥不进入镜像、仓库或前端 bundle。
- [ ] **AC-017** 管理操作、订单状态和链同步异常可检索并带完整 correlation/audit 信息。

## 依赖

- Privy（身份与嵌入式/外部钱包）。
- PostgreSQL；Redis + SQS（缓存、任务与死信队列，最终选型见设计）。
- Go 1.24+、HTTP Router、pgx/sqlc 或等价的强类型数据库层。
- Foundry、Solidity 0.8.24、OpenZeppelin Contracts。
- wagmi v2、viem v2、TanStack Query；现有 Web 为 Vite + React，若迁移 Next.js 需单独 ADR。
- EVM RPC、区块浏览器 API、Uniswap v3/v4 SDK/合约、Chainlink 服务。
- AWS ECS/Fargate、RDS PostgreSQL、S3、CloudFront、ALB、SQS、ElastiCache、Secrets Manager、KMS、CloudWatch、WAF。

## 开放问题

- **OQ-001** 生产目标链、确认数、支持的钱包类型和 gas 代付策略是什么？
- **OQ-002** YD 总量、分配、增发/销毁、暂停、treasury 多签和监管定位如何确定？
- **OQ-003** 课程款直接进入 treasury，还是采用老师分账、延迟结算和退款窗口？
- **OQ-004** 课程定价只允许 YD，还是同时支持稳定币；YD 价格波动由谁承担？
- **OQ-005** 视频转码/DRM 使用 AWS MediaConvert/MediaPackage 还是外部视频服务？
- **OQ-006** 完课规则仅依赖平台事件，还是需要考试、老师审核或外部证明？
- **OQ-007** Chainlink 在 MVP 中的具体不可替代用例是什么？若无，建议延后。
- **OQ-008** Next.js 是强制迁移要求还是历史方案？当前仓库是 Vite + React，MVP 默认保留以降低迁移风险。
